0001 — Cargo runs the shop

One concept: a Rust project is a Cargo project — one manifest describes it, a handful of commands drive it. One win: your playground/ ends this lesson rustfmt-clean and Clippy-clean, and you know what every file in it is for. That is step zero of the mission's "passes Clippy, looks like experienced Rust" bar.

1 · Recall first (no peeking)

You have built two Cargo projects already, so this should be in there somewhere. Answer from memory, then open the reveal.

You ran cargo new playground a year ago. Which files did it create, and what is each one for?

Cargo.toml (the manifest — your declarations), src/main.rs (the entry point), plus .gitignore and a git repo. Full anatomy in §2 — check what you missed.

What two things does cargo run do, in order?

cargo run = build, then execute target/debug/<name>. If that was a guess, the command table in §2 will cement it.

2 · The knowledge (five minutes)

Here is your playground/, annotated. Every claim below is grounded in Book §1.3, "Hello, Cargo!" (online mirror).

playground/
├── Cargo.toml    # the MANIFEST: name, edition, dependencies — you edit this
├── Cargo.lock    # exact resolved dependency versions — Cargo edits this
├── src/
│   └── main.rs   # entry point: `fn main` lives here
└── target/       # build artifacts (gitignored) — safe to delete anytime

Two distinctions that matter for the whole course:

  • You edit Cargo.toml; Cargo owns Cargo.lock. The manifest says "I need rand 0.9"; the lockfile pins the exact version that built. (Your .gitignore ignores target/ but keeps Cargo.lock — correct for a binary.)
  • println! is a macro, not a function — the ! says "expand this at compile time" (Book §1.2, mirror). Macros return to haunt us pleasantly in later lessons; for now, just read ! as "macro".

cargo newScaffolds manifest + entry point + git repoOnce per project

3 · Hands-on: clean your own project

Step 1 — predict. I ran cargo fmt --check on your playground/ and it failed. Before running anything, guess: what will it complain about? (Hint: look at the indentation in playground/src/main.rs.)

Reveal after guessing

Indentation. The file uses 2-space indents; rustfmt demands 4. Nothing semantic — pure style, which is exactly what fmt owns.

Step 2 — see it. Run cargo fmt --check in playground/. Checkpoint: you see a diff touching only whitespace.

Step 3 — apply it. Run cargo fmt, then git diff. Checkpoint: the diff shows indentation changes and nothing else. Your code now matches what every Rust developer's editor produces.

Step 4 — lint it. Run cargo clippy in playground/, then in guessing_game/. Checkpoint: both are clean (I verified — zero warnings). That silence is the result: Clippy-clean is the mission's baseline, and you now know how to check it.

4 · Lock it in

You add the rand crate. Which file do you edit?

Dependencies are declared in Cargo.toml; Cargo updates the lockfile itself. (Your guessing_game manifest already shows this.)

What does cargo check give you?

check skips code generation, so it is the fastest correctness feedback — use it while editing, build when you need to run.

You delete target/. The next cargo run will…

target/ holds only regenerable artifacts (that is why it is gitignored). Deleting it costs a rebuild, nothing more.

The ! in println! means…

!suffix marks a macro invocation. Functions never end in ! — a reliable visual cue when reading unfamiliar code.
